02
What it does · end to end

From a blank list to a booked meeting — one continuous run.

dispatch pipeline

kural runs a deterministic spine — an ADK SequentialAgent (qualify → research → market intel → write → fact-check → send) — with a parallel research burst in the middle. Each stage hands its work to the next via output_key → {placeholder} with a Pydantic output_schema and locked sub-agent boundaries; nothing is sent until the after_agent LLM-as-judge gate clears it.

1FIND

Discover & qualify prospects

The Coordinator builds the target set from your ideal-customer profile and decides what is actually worth pursuing — not everyone makes the cut. Weak fits are dropped before a cent of research is spent.

Coordinator · Claude via Vertex AI · qualify decision

Research every prospect in parallel

The Researcher is a real ParallelAgent fan-out — one research task per company, all at once — grounded on live Google Search and Vertex AI Search. Funding, hiring, product launches, the named buyer, recent posts. Real facts, with sources. The fan-out is modeled on the enterprise parallel_task_decomposition_execution sample.

Researcher · Gemini · ParallelAgent fan-out · modeled on parallel_task_decomposition_execution
3ANGLE

Read the signals, find the angle

Market / Growth Intelligence · Gemini
4WRITE

Draft the tailored message

The Personalisation Writer drafts outreach built on the angle and the facts — specific, short, and addressed to a real person, not a merge field. One message per prospect, never a template blast.

Personalisation Writer · Gemini
5VERIFY

The after_agent judge — fact-check, score, gate

The Fact-Checker runs as an after_agent LLM-as-judge: it verifies every claim against the cited research and scores the message on a rubric (tone, anti-spam, brand policy, claim support). Below the 0.8 bar — the same rubric-judge pattern as the small-business-loan sample — the message is sent back to the Writer, never sent out.

Fact-Checker · Claude via Vertex AI · after_agent LLM-as-judge gate @0.8 (small-business-loan rubric)
6SEND

The judge clears the gate — then the safe-by-construction send

Once the after_agent judge clears it, the Sender is safe by construction: a before_tool callback re-checks eligibility and value caps, a confirm-before-send step gates the irreversible call, and a Firestore pause / repair / resume ledger means a crash can never double-send. Only then does the Sender send the email as the buyer (OAuth) and book the meeting on their calendar — OTel-traced, logged to BigQuery.

The agent team · the org chart

Seven specialists on a spine, two models. The team beats any single agent.

technical · 30%

A single chatbot writing a cold email is a toy. kural wins because work moves down a SequentialAgent spine of specialists who each do one thing well, and the two highest-stakes judgments — who is worth pursuing, and whether a message clears the send gate — run on Claude via Vertex AI, while Gemini powers the high-volume routine agents. Both models, one Google Cloud runtime. kural is the company's only mouth: the Coordinator decides, the spine works, and only the Sender (outreach email + booking) and the Publisher (the social channel keys) ever touch the outside world — each behind a gate.

05
How it's built · the stack

A SequentialAgent spine, scaffolded, evaluated, observed, and deployed to Agent Engine.

technical · architecture

kural is scaffolded with the agent-starter-pack and built on Google's Agent Development Kit, running entirely on Google Cloud. Gemini powers the many routine agents; Claude (Sonnet / Opus) runs through Vertex AI Model Garden for the two highest-stakes decision agents. It ships with a checked-in eval set, OTel + BigQuery observability, and a safe-by-construction action gate — the Google-grade bar, not a demo.

Scaffold
agent-starter-pack layout. A root_agent in agent.py, externalised prompts/ and tools/, a checked-in eval/ set, tests/, and deployment/deploy.py — the standard Google-grade project shape, not a single notebook.
Orchestration
Google ADK SequentialAgent spine. A SequentialAgent (qualify → research → market intel → write → fact-check → send) hands each stage on via output_key → {placeholder} with a Pydantic output_schema and locked sub-agent boundaries; a ParallelAgent fans research out; the Fact-Checker runs as an after_agent LLM-as-judge gate that sends a failing draft back to the Writer.
Models
Gemini for the routine, high-volume agents · Claude via Vertex AI Model Garden for the Coordinator's qualification and the Fact-Checker's after_agent judge gate.
Researcher · Gemini Intelligence · Gemini Writer · Gemini Sender · Gemini Publisher · Gemini Coordinator · Claude / Vertex Fact-Checker · Claude / Vertex
Grounding / RAG
Vertex AI Search + Google Search grounding on every research task, so outreach claims trace back to real, cited sources — not model guesses.
Memory
Sessions hold a single dispatch run; Memory Bank remembers accounts, prior touches, and what was already said — so kural never emails the same person the same thing twice.
Eval
Checked-in eval set. An AgentEvaluator runs the eval set in CI, plus a rubric LLM-as-judge scoring outreach quality and claim support against a 0.8 bar — the same rubric-judge pattern as the small-business-loan sample. Regressions fail the build, not the buyer's inbox.
Observability
OpenTelemetry traces every agent + tool span (NO_CONTENT so prospect data never leaves the trace), and a BigQuery analytics plugin logs every run for reply-rate and cost analytics — mandatory telemetry for a B2B agent a buyer actually hires.
Identity / Auth
Real auth, per request. The email + meeting are sent as the buyer over OAuth (or a service account + IAM via Secret Manager) — never a shared key. Identity is propagated per request so every action is attributable to a real principal.
Runtime
Vertex AI Agent Engine (primary). Deployed via deployment/deploy.py, managed and autoscaling, with Cloud Run + IAP as the secondary path. Per-tenant isolated — a true Marketplace deployment a buyer provisions into their own Google Cloud project. Always-on cadence via Cloud Scheduler + OIDC.
Interop
A2A + MCP. kural is exposed over A2A via to_a2a() with a published Agent Card and a StreamableHTTP MCP server, so a buyer's existing CRM and calendar agents can discover kural and hire it — coordinating work agent-to-agent.
Safe action
Safe-by-construction send. Email + calendar tools sit behind a before_tool eligibility + value-cap gate, a confirm-before-send step, and a Firestore pause / repair / resume ledger so a crash never double-sends. Only the Sender can fire them, and only after the judge clears — the live send is the credibility edge (every GTM sample stubs it as a mock). The Publisher is the sole holder of the social channel keys (X / IG / LinkedIn); it formats kalai's approved master per channel and posts only behind the founder's publish sign-off — kural is the company's only mouth.
