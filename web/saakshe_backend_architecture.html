01 The shape, corrected

arivu is not a standalone product — it is the chamber the agents step into. There is one front door.

There is one product — saakshe, the witness. The founder talks only to it: chat and voice. The four quadrants — manas (knows), arivu (decides), kalai (makes), kural (engages) — are backends wired behind saakshe. They speak to each other over A2A; they never speak to the founder. arivu is no longer a front door with its own console — it becomes one module inside the unified service.

Everything connects through a single FastAPI service and a single ordered event stream. The submission is “the agentic company + its witness,” not five sites.

02 One service, four agents, one stream

Unify at the server / orchestrator / stream layer. Each quadrant stays a clean ADK module exposing root_agent; a shared common substrate carries the seams. arivu (already green, 29 tests) is left untouched.

05 Why saakshe is itself an agent

Not a dashboard with a chatbot. The witness answers only from live telemetry, and refuses what the stream can’t support — that refusal is the agent.

tools-over-telemetry

The witness holds no static knowledge. Every answer is a tool call against the live stream:

  • “anyone waiting on me?” → reads the gate queue
  • “what did today cost?” → aggregates agent_events
  • “what’s reversible?” → reads current flow state
  • “what did manas learn?” → the Context Pack ticker

the refusal beat (scripted, first-class)

Founder: “how much did we spend on ads today?”

saakshe: “There’s no ‘ads’ bucket in the stream. I can see 3 posts, 2 DMs, 4 replies through kural — which did you mean?”

It will not invent a number it cannot see. Voice rides the same tools over Gemini Live; the creds-free demo exercises them over text.

setu — the bridge, folded in

Permission is a quality of the four, not a fifth product: source grants (manas reads only what you patched), scope grants (kural speaks only through scopes you threw), gate strictness, safe defaults (every fresh connection read-only + gated), deep audit (every act stamped source → permission → approval). This is why saakshe can refuse — it sees exactly what it knows and what power it holds.

06 Demo-first — live is one flag

Every quadrant, the witness, and the whole flywheel run end-to-end with no credentials — deterministic replay, exactly as arivu does today. The reasoning is real ADK orchestration; only token generation is scripted until creds land.

DEMO  SAAKSHE_MODE=demo — Parallel / Loop / escalate / HITL / executor all fire for real; scripted models stand in for Gemini + Claude. Survives a 429 mid-demo. This is what runs in the video.

LIVE  Gemini via Vertex (global) + Claude via Vertex Model Garden (us-east5). One flag flips the model factory; the stream, gates, A2A, and executor shapes are identical — no rewrite.

SETUP  Live models need a GCP project + ADC, with an Anthropic model enabled in Vertex Model Garden for that project in us-east5 (the per-project step people miss). Voice (Gemini Live) is live-only by nature — the wiring ships now; the demo shows the same tools over text.

07 How it was built — skeleton first, then deepened

The cross-quadrant seams were locked in code and proven end-to-end first; each quadrant was then deepened additively on a green base. Integration is what eats projects — so integration came first.

Phase A
Common substrate + walking skeleton. The common layer (config · models · the event stream · A2A) locks three contracts: the stream row, the A2A handoff payloads, the orchestrator↔quadrant signatures. The orchestrator, real arivu, thin-but-real manas/kalai/kural and a thin witness prove the full flywheel in demo with both gates. The seams are locked by being real.
Phase B
The three quadrants deepened — manas / kalai / kural each lifted to arivu quality: real Parallel/Loop agents, Claude-gated high-stakes calls, per-quadrant tests, demo fixtures that produce the sealed canon numbers, eval @0.8. Additive — the skeleton stayed green.
Phase C
Witness + unified server. The telemetry tools + the principled refusal beat + the Gemini Live voice bridge; one FastAPI service mounting the witness, four quadrants, the 2-gate hero loop, the stream, and voice. arivu’s existing API preserved.
Phase D
Cockpit live mode + verification. A live data-source seam behind the cockpit (demo replay stays the default; layout untouched), with perception + behavior harnesses re-run for zero regression across the whole flywheel.

Demo-first by design. Nothing here requires credentials to run — the full flywheel, both human gates, and every quadrant execute end-to-end in deterministic replay. Live mode is one flag once a GCP project with Vertex access is wired.
