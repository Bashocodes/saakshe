The honest verdict

The agentic skeleton is real. The agentic intelligence is half-real. The experience you want to show judges — "connect a repo and watch agents interview the founder" — exists at roughly 15–20%, and it is physically unreachable on the deployed site.

Your instinct was right, with one important correction: it's not that "we haven't even started" — the repo ingestion genuinely clones and reads real repos, and a clarifying-question mechanism genuinely exists and folds answers back into memory. But the questions are six hardcoded English templates (not LLM-generated, not varied, not conversational), there is no cockpit UI to display or answer them, and the gated prod demo seals the entire connect surface — a judge on saakshe.com today cannot connect anything.

1 · Your core question: "What happens when a repo is connected? What questions do the agents ask?"

What actually exists (more than you thought)

  1. Connect is real storage, not ingestion. POST /api/connect/source just stores the URL service/app.py:330. Nothing happens until POST /api/connect/ingest is called manually — there is no auto-trigger.
  2. Ingestion is genuinely real. manas shallow-clones the actual repo (git clone --depth 1), reads README, package.json, directory structure and docs/ manas/sources.py:89–154; fetches the website and key pages over httpx; extracts org name and one-liner; pulls brand images into the vault.
  3. Real Gemini extracts the knowledge. Four parallel "imbiber pods" (one per source channel, each with 4 sub-readers: claims / voice / brand / contradiction) run live gemini-3.5-flash over the real text and produce cited facts manas/imbiber_pod.py:141, runner.py:77–166. This part is live in prod's hybrid mode.
  4. Questions ARE raised — but by code, not by agents. doubts.detect() runs deterministic rules and surfaces ClarifyingQuestion objects in the ingest response manas/doubts.py:75–136.
  5. Answers genuinely fold back. POST /api/connect/answer turns the founder's answer into a cited fact ("founder answer · qid"), re-runs curation, and ticks the Context Pack version manas/runner.py:243–264. This loop is real and tested.

Three blockers between today and the demo you want

  1. No UI. The cockpit fetches questions and even has the answer endpoint wired in JS web/cockpit.html:2829–2843, but there is no rendered question card / answer form. A judge would never see the questions unless they read the raw stream and curl the API.
  2. Sealed in prod. The gated profile sets SAAKSHE_PUBLIC_DEMO=1, which seals /api/connect/source, /api/connect/ingest, /api/connect/reset and /api/vault/add service/app.py:332,353,383,401 · deploy_cloudrun.sh:46. The live "connect a repo" demo is impossible on saakshe.com as deployed. It works only locally or with a profile that unseals connect.
  3. Not an interview. The vision — agents curiously probing the founder with varied, intelligent, context-derived questions — is not built. What exists is a clarification valve (6 templates) bolted to a real ingestion pipeline. The docstring itself admits questions "could be Gemini-written later" manas/doubts.py:13.

2 · The agentic system that IS genuinely functional

This is the part you can defend with a straight face. It's not theater — 334 tests exercise the real orchestration (only token generation is stubbed in CI), and these run identically with live models:

  • A real 2-gate flywheel state machine — manas grounds → arivu deliberates → Gate 1 (founder taps) → arivu executes (dry) → kalai makes → kural engages → Gate 2 (founder taps) → publish (dry) → manas learns, memory version ticks. Fail-closed at every step: if kalai or kural blocks, the run ends in no_safe_decision, never forced through. orchestrator.py:127–329
  • Restart-proof runs — flywheel state persists to the store and rehydrates after a container restart. orchestrator.py:66–113, tests/test_flywheel.py:83–96
  • Real versioned memory with a refusal contract — manas commits only cited facts past a deterministic groundedness ≥ 0.80 check (rollback otherwise), and founder-voice refuses to answer anything out-of-corpus rather than inventing. manas/agent.py:71–94, tools/corpus.py:111–123
  • Live Gemini at every routine seat in prod — imbibers, arivu's 5-advisor panel + debate, kalai's designer/copy/4-scorer fidelity loop, kural's 4 delivery readers all hit real gemini-3.1-pro / 3.5-flash in the deployed hybrid. deploy_cloudrun.sh:28, common/models.py:83–92
  • A real image pipeline — Vertex Imagen fires only after fidelity + compliance clear, bytes persist to the vault, and the render displays on the gate-2 card. A real render is checked in as proof (docs/first_creation.png). kalai/runner.py:172–235, media.py:116–125
  • An honest witness — telemetry Q&A reads only the event stream and refuses what it can't see ("I won't invent a number"). Deterministic, never hallucinates. witness/agent.py:48–95
  • Real safety engineering — publish requires a triple AND-gate (SAAKSHE_ALLOW_LIVE_SEND=1 + per-tap arm_real_send + a registered channel client), a no-double-send ledger, and dry-run hardcoded as default. orchestrator.py:204–252

Caveat on "A2A": agent-to-agent calls are an in-process registry with the right call shape, not network message passing — the agent card itself admits the JSON-RPC endpoint "is NOT yet wired." common/a2a.py:18,196–230

6 · Hackathon readiness: can you show this live?

The live demo you CAN run today (locally / unsealed profile)

  1. Connect a real GitHub repo + website → watch the real clone, real Gemini extraction, real cited facts stream in, Context Pack commit v1.
  2. Show the clarifying questions in the ingest response (via stream/API — be honest that the UI form is coming), answer one, watch the pack tick to v2.
  3. Ask a pricing-shaped decision question → real Gemini advisor debate → Gate 1 tap → real Gemini studio + real Imagen render appearing on the gate-2 card → Gate 2 tap → dry-run publish → manas learns, version ticks.
  4. Ask witness "who's acting now?" and "what did we spend on ads?" → live answer + an honest refusal. Judges love the refusal.

The traps that will burn you live

  1. The verdict is always "$34 Pro tier." Scripted Claude returns the same pricing verdict for ANY question. Ask "should we launch on Product Hunt?" on a fresh repo and the chamber will answer about grandfathering Pro subscribers — instantly exposing the script. Until Claude quota lands, only demo decision questions that fit the pricing storyline, or say out loud "the verdict seat is a replayed transcript while our Vertex quota clears" (your own SUBMISSION.md already says this).
  2. Don't demo connect on prod — it's sealed and will 403. Run the connect demo on a local/unsealed instance.
  3. Don't claim delivery — nothing has ever been published anywhere; the URLs are placeholders.
  4. Fresh-repo kalai looks generic — with no brand assets ingested the "brand fidelity" climb is judging an empty bank. Connect a repo that has a logo + real docs so the vault and brand block populate.

Are we ready?

For Track 1 as submitted (gated AIKIZI-seeded demo + honest hybrid disclosure): yes, defensible. The orchestration, gates, memory, and Gemini seats are real, and the submission doc doesn't lie. For the demo you actually want to give — live repo connect + agents interviewing the founder: no. That needs roughly the four items below.
